## Задача

Консольная программа загружает заявки на выдачу книг из файла, проверяет их и
обслуживает по возрастанию номера. Очередь выдач, стек возвратов и связный список
истории реализованы вручную на узлах. Для поиска по ISBN используется словарь.
Программа поддерживает возврат и отмену выдачи, разворот истории, статистику по
разделам и сохранение отчёта.

## Запуск

Нужен Python 3.9 или новее. Сторонние библиотеки не требуются.
Из корня репозитория:

```bash
python3 lab_03/main.py
```

Из папки лабораторной:

```bash
python3 main.py
```

Файлы `issues.txt` и `issues_report.txt` находятся рядом с `main.py`, поэтому
их расположение не зависит от текущей папки терминала. Отчёт сохраняется пунктом 9
меню. При повторном запуске очередь загружается заново, история и стек пусты.

При каждом запуске перед меню автоматически выполняется `run_asserts()`.
При успешном выполнении выводится `Все автоматические проверки пройдены.`,
после чего программа загружает данные и открывает меню.
Проверки используют временную папку и не изменяют рабочие входной файл и отчёт.

## Формат входного файла

Файл `issues.txt` хранится в UTF-8 без строки заголовков. Формат непустой строки:

```text
номер;читатель;isbn;раздел;название
```

Номер должен быть положительным целым числом. Номер и ISBN уникальны среди
принятых записей. Все текстовые поля обязательны; пробелы по краям удаляются.
ISBN проверяется на заполненность и уникальность: контрольная сумма по ТЗ
не проверяется. Пустые строки пропускаются.

Корректная запись:

```text
2001;Иванов Иван;978-5-17-145822-9;техника;Занимательная физика
```

Некорректная запись с пустым ISBN:

```text
2013;Тестовый читатель; ;история;Пустой ISBN
```

Для неё сохраняется сообщение `Строка 13: пустое обязательное поле: 'isbn'.`
Ошибка одной строки не мешает загрузке остальных. Номер и ISBN отклонённой
записи не занимают место среди корректных записей.

Подготовленный файл содержит 16 непустых строк: 10 корректных и 6 некорректных.
Есть четыре раздела и записи с нарушенным порядком номеров, чтобы проверить
сортировку очереди.

## Структура программы

| Файл | Назначение |
| --- | --- |
| `main.py` | Разбор файла, операции выдачи и возврата, поиск, статистика, меню, отчёт и `run_asserts` |
| `data_structures.py` | Классы `Node`, `Stack`, `Queue`, `LinkedList` и рекурсивные функции |
| `issues.txt` | Входные записи, включая примеры ошибок |
| `issues_report.txt` | Пример отчёта, сформированного программой |

Каждая запись представлена словарём с ключами `number`, `reader`, `isbn`,
`section`, `title`. Функция `load_issues` возвращает очередь, словарь по ISBN,
список ошибок и число корректных записей. Основные данные создаются в `main`
и передаются функциям через параметры.

## Структуры данных и операции

| Структура | Операции и назначение |
| --- | --- |
| `Node` | Значение `value` и ссылка `next` на следующий узел |
| `Queue` | `enqueue` добавляет в хвост за O(1), `dequeue` извлекает из головы за O(1); `is_empty` проверяет пустоту, `__iter__` перебирает значения по узлам без временного списка. Порядок FIFO |
| `Stack` | `push` и `pop` работают с вершиной за O(1); `remove_value` ищет ISBN и удаляет его за O(n). Порядок LIFO |
| `LinkedList` | `append` добавляет в хвост за O(1); `find` рекурсивно ищет ISBN за O(n); `to_list` рекурсивно обходит историю; `reverse` меняет ссылки за O(n) |
| `dict` | Хэш-таблица `ISBN -> запись`, поиск по строковому ключу занимает O(1) в среднем |
| `set` | Множество уникальных разделов и множество принятых номеров |

У каждой собственной структуры есть `__repr__`. Извлечение из пустых очереди
и стека выбрасывает `IndexError`. Функции обслуживания обрабатывают пустые
структуры и возвращают `None` или `False`, а меню выводит понятное сообщение.

Основное хранение очереди и истории организовано на узлах. Встроенные списки
остались только для ошибок загрузки (пункт 6.1 ТЗ) и результата рекурсивного
обхода истории (пункт 6.5 ТЗ), включая проверки этих результатов.
ТЗ запрещает готовые списки для основного хранения выдач, а не вообще все списки.

Строка разбирается через `partition` в отдельные переменные, без `split`
и спискового включения. Очередь выводится непосредственно по узлам.
Статистика формируется строкой, отчёт записывается сразу в файл,
а строковые представления структур создаются без промежуточных списков.
При загрузке очередь сортируется выбором прямо на узлах: на каждом шаге
находится минимальный оставшийся номер и меняются местами значения двух узлов.
Промежуточный список не создаётся. Сортировка занимает O(n²) времени и O(1)
дополнительной памяти; данные самих записей не изменяются.
`collections.deque` не используется.

## Поведение операций

При выдаче запись удаляется из головы очереди, её копия добавляется в конец
истории, а ISBN кладётся на вершину стека возвратов. Возврат по ISBN удаляет
нужный узел из стека, в том числе из середины.

Отмена по пункту 6.4 ТЗ снимает верхний ISBN со стека. Запись остаётся в истории
и обратно в очередь не добавляется. Статистика учитывает все фактические выдачи
из истории; число невозвращённых книг определяется текущим стеком. Заявки,
которые ещё находятся в очереди, выдачами не считаются.

Для каждого раздела выводятся число выдач, число невозвращённых книг, номер
последней выдачи и максимальный номер. Последние два значения совпадают, так
как номера порядковые. Для разделов без выдач выводятся нули и прочерки.
Разделы берутся из всех корректных записей и выводятся по алфавиту.

Разворот меняет саму историю. Следующая выдача добавляется в конец её текущего
порядка. Разворот не меняет стек и статистику. В пункте 8 можно сравнить поиск
во всём каталоге через словарь и рекурсивный поиск только в истории выдач.

## Ссылочная модель

Переменная хранит ссылку на объект: присваивание `b = a` не создаёт копию.
Очередь и индекс ISBN ссылаются на одни загруженные записи, которые операции
обслуживания не изменяют. История хранит независимые копии записей.
`issue_book`, `get_history`, `find_book` и `find_in_history` возвращают копии
через `deepcopy`, чтобы изменение результата не затронуло внутренние данные.
Метод `LinkedList.to_list` создаёт новый список со ссылками на значения узлов.
Обход очереди через `__iter__` возвращает значения по одному без их копирования.

Мутации выполняются только там, где они нужны: выдача меняет очередь, историю
и стек; возврат и отмена меняют стек; разворот меняет ссылки истории.
Поиск, статистика, вывод и сохранение отчёта не меняют исходные коллекции.
В аргументах по умолчанию используются неизменяемые значения или `None`.
Для алфавитного вывода разделов создаётся копия множества названий. Из неё
последовательно берётся минимальное название. Исходное множество и записи
не изменяются; промежуточный список не создаётся.

Ключи словаря ISBN являются неизменяемыми строками. Список нельзя сделать
ключом словаря, поскольку он изменяем и не хэшируется; для ключа из множества
элементов подошёл бы `frozenset`.

При развороте сначала сохраняется ссылка `next_node`, затем меняется `next`:
так оставшаяся цепочка не теряется. Удаление из середины стека связывает
предыдущий узел со следующим без сдвига значений. Поиск места удаления занимает
O(n), а само изменение ссылки после поиска - O(1).

## Обработанные ошибки и проверки

Обрабатываются отсутствие или недоступность файла, неверная кодировка,
неверное количество полей, нецелый или неположительный номер, повтор номера
или ISBN и пустые обязательные поля. Для некорректной строки сохраняются её
номер и причина; при нескольких нарушениях сообщается первое найденное.

Меню обрабатывает пустую очередь, пустой стек, возврат неизвестного или уже
возвращённого ISBN, отсутствие результатов поиска, пустую историю и набор
для статистики, неизвестный пункт, ошибку записи отчёта и завершение ввода.

`run_asserts` проверяет FIFO и LIFO, `IndexError` на пустых структурах, удаление
из середины стека, повторный возврат, сортировку загрузки, все виды ошибок
строк, рекурсивный поиск и обход, разворот и добавление после него, статистику,
запись отчёта, независимость копий и отсутствие накопления состояния.

2
